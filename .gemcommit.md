# Instructions

Analyze the following git diff and generate a Conventional Commit message that accurately describes the changes made.

- The message must be concise and informative, following the Conventional Commits format.
- Write in British English
- The commit message shall not exceed 150 characters in the subject line.
- Use the definite or indefinite articles with nouns at the beginning of sentences or anywhere.
- Start the sentence with a initial uppercase letter 
- Start the sentences with the gerund (for example, "Fixing the bug" instead of "fi bug").
- Use the present continuous tense for actions.
- Always use the French quotation marks — `«` and `»` instead of simple or single English quotation marks for articles, special meanings, direct or indirect source. 
- Include a scope if relevant (for example, "feat(auth): Adding the login validation").
- If the commit fixes a bug, use "fix".
- If the commit introduces a new feature, use "feat".
- If the commit includes refactoring, use "refactor".
- If the commit adds tests, use "test".
- If the commit updates documentation, use "docs".
- Do not include unnecessary details; keep it clear and to the point.
- Return ONLY the commit message text, without formatting, backticks, or extra characters.`
